# Claude Code をクラウドで動かしてみよか — Cloud Code のすすめ

## そもそも Cloud Code てなんやねん？

「開発環境のセットアップ、ちょっとめんどいなぁ……」って思たことない？

Claude Code は Anthropic の AI コーディングエージェントやねんけど、実はターミナルや IDE だけちゃうて、**ブラウザからクラウド上でそのまま動かせる**んですわ。この記事では、その「クラウド版 Claude Code（Cloud Code）」について、気軽に使いはじめられるようにゆる〜っと紹介していくで。

> ここで言う「Cloud Code」は、`claude.ai/code` とかからブラウザ経由で立ち上げられる Claude Code のことや。手元に何もインストールせんでも、クラウド上の隔離された環境のなかでエージェントが動いてくれるっちゅうわけ。

## ローカルと何がちゃうん？

ざっくり比べたら、こんな感じや。

| 項目 | ローカルで動かす | クラウドで動かす |
| --- | --- | --- |
| 実行場所 | 自分のマシン | クラウド上の隔離コンテナ |
| セットアップ | CLI のインストールが必要 | ブラウザだけでええ |
| リポジトリ | 手元のクローン | セッション開始時に自動でクローン |
| ライフサイクル | ずっと残る | しばらく放っとくと自動でお片付け |
| 起動元 | ターミナル / IDE | Web・スマホ・デスクトップ・GitHub Actions など |

いっちゃんうれしいのは、やっぱり**「ブラウザだけで始められる」**とこやな。思い立ったときに、その場でサッと開発を頼めるんや。

### コンテナは“使い捨て”やで

クラウドのセッションは、**その都度立ち上がる使い捨てのコンテナ**のなかで動くねん。起動したらリポジトリが新しくクローンされて、しばらくいじらんかったら（あるいはセッションが終わったら）コンテナはきれいさっぱり片付けられてまう。

ここでめっちゃ大事なポイントがひとつ。**残しときたい変更は、かならずコミットしてプッシュ**しときや。プッシュせんままコンテナが消えたら、せっかくの作業がパァになってまうからな。ここだけはホンマ忘れんといてや！

### ネットワークの設定について

外への通信は、環境ごとに決めた**ネットワークポリシー**でコントロールされんねん。環境を作るときに選べて、環境変数やセットアップスクリプトも一緒に用意できるで。プロジェクトに合わせて自由に整えられるさかい、安心してや。

## こんなときに便利やで

- **どこからでも開発したい**: 手元に環境なくても、ブラウザさえあれば作業を頼めるで。カフェでもスマホからでもいける。
- **GitHub まわりを自動化したい**: PR のレビュー対応や、CI がコケたときの修正、Issue からの実装なんかも、まかせられる。
- **なんぼも並行で進めたい**: セッションを複数立ち上げたら、それぞれ別のコンテナで独立して作業が進むで。
- **まっさらな環境で試したい**: 毎回きれいなクローンから始まるさかい、ローカルの状態に振り回されへん。

## GitHub との相性がええ

Cloud Code は GitHub との連携がめっちゃ得意や。

- PR やコメント、CI の状況を見たり作ったり
- PR のレビューコメントへの返信
- CI が落ちたときの原因調べて自動で修正

「この PR 見張っといて」て頼んだら、CI の結果やレビューコメントを受け取って、そのつど対応してくれるんや。しかも、イベントが来たら自動でセッションが起きてくれるさかい、**こっちが張り付いて待っとく必要はあらへん**。ここ、地味にありがたいポイントやで。

## はじめ方はかんたんや

1. **環境を用意する**
   ブラウザで Claude Code のクラウド環境（`claude.ai/code` とか）を開くねん。対象のリポジトリやネットワークポリシー、環境変数、セットアップスクリプトを設定しとこか。

2. **セッションを始める**
   リポジトリを選んでセッションを立ち上げたら、コンテナが起動してリポジトリが自動でクローンされるで。ここまで待つだけや。

3. **やりたいことを伝える**
   「この関数のバグ直して」「テスト足しといて」みたいに、ふつうの言葉でお願いしたらええ。エージェントがコードを読んで、直して、必要ならテストも走らせてくれるで。

4. **コミット & プッシュ**
   できあがったら、コミットしてブランチへプッシュや。くどいようやけど、**プッシュせんと成果は残らへん**さかい、ここだけはホンマにお忘れなく。

## セットアップスクリプトで最初から快適に

プロジェクトによっては、テストやリンターを動かすのに依存関係のインストールが要るやんな。そんなときは **SessionStart フック**やセットアップスクリプトの出番や。セッションが始まったタイミングで自動で環境を整えてくれるさかい、Web セッションでもローカルと同じように `npm test` や lint がすんなり動く状態を作れるんや。最初にちょっと仕込んどいたら、あとがぐっとラクになるで。

## ちょっとした注意点

- **ディスクは固定枠**: 書き込めるディスクはセッションごとの固定枠や。`No space left on device` が出ても慌てんでええ。いらんビルド成果物やキャッシュを消したら、その分すぐに書けるようになるで。
- **成果はかならずプッシュ**: なんべんも言うてすまんな。でもホンマに大事やから！ 残したい変更はコミット & プッシュを忘れんといて。
- **ブラウザは最初から入ってるで**: Chromium がプリインストール済みで、Playwright も設定済み。`playwright install` を実行する必要はあらへん。

## ほな、まとめや

Cloud Code のええとこは、なんちゅうても**「環境に縛られへんで、どこからでも AI にサッと開発を頼める」**とこや。使い捨てのきれいなコンテナ、GitHub との仲のよさ、開始時の自動セットアップ——このへんがそろっとるおかげで、スマホからの指示や PR の自動対応みたいに、今まで手間やった作業がずいぶんラクになるんや。

まずは小さなタスクからで大丈夫。気軽にブラウザから Claude Code に話しかけてみてや。きっと「あ、これ便利やん」て思えるはずやで 🙂
