# Claude Code をクラウドで動かしてみよう — Cloud Code のすすめ

## そもそも Cloud Code って？

「開発環境をセットアップするの、ちょっと面倒だな……」って思ったこと、ありませんか？

Claude Code は Anthropic の AI コーディングエージェントですが、実はターミナルや IDE だけでなく、**ブラウザからクラウド上でそのまま動かせる**んです。この記事では、その「クラウド版 Claude Code（Cloud Code）」について、気軽に使いはじめられるようにゆるっと紹介していきます。

> ここで言う「Cloud Code」は、`claude.ai/code` などからブラウザ経由で起動できる Claude Code のことです。手元に何もインストールしなくても、クラウド上の隔離された環境の中でエージェントが動いてくれます。

## ローカルと何が違うの？

ざっくり比べると、こんな感じです。

| 項目 | ローカルで動かす | クラウドで動かす |
| --- | --- | --- |
| 実行場所 | 自分のマシン | クラウド上の隔離コンテナ |
| セットアップ | CLI のインストールが必要 | ブラウザだけでOK |
| リポジトリ | 手元のクローン | セッション開始時に自動でクローン |
| ライフサイクル | ずっと残る | しばらく放置すると自動でお片付け |
| 起動元 | ターミナル / IDE | Web・スマホ・デスクトップ・GitHub Actions など |

一番うれしいのは、やっぱり**「ブラウザだけで始められる」**ところ。思い立ったときに、その場でサッと開発を頼めます。

### コンテナは“使い捨て”です

クラウドのセッションは、**その都度立ち上がる使い捨てのコンテナ**の中で動きます。起動するとリポジトリが新しくクローンされて、しばらく操作しないと（あるいはセッションが終わると）コンテナはきれいに片付けられます。

ここで大事なポイントがひとつ。**残しておきたい変更は、必ずコミットしてプッシュ**しておきましょう。プッシュしないままコンテナが消えると、せっかくの作業がなくなってしまいます。ここだけは忘れずに！

### ネットワークの設定について

外部への通信は、環境ごとに決めた**ネットワークポリシー**でコントロールされます。環境を作るときに選べて、環境変数やセットアップスクリプトも一緒に用意できます。プロジェクトに合わせて自由に整えられるので安心です。

## こんなときに便利

- **どこからでも開発したい**: 手元に環境がなくても、ブラウザさえあれば作業を頼めます。カフェでもスマホからでも。
- **GitHub まわりを自動化したい**: PR のレビュー対応や、CI が失敗したときの修正、Issue からの実装など、おまかせできます。
- **いくつも並行で進めたい**: セッションを複数立ち上げれば、それぞれ別のコンテナで独立して作業が進みます。
- **まっさらな環境で試したい**: 毎回きれいなクローンから始まるので、ローカルの状態に振り回されません。

## GitHub との相性がいい

Cloud Code は GitHub との連携がとても得意です。

- PR やコメント、CI の状況を見たり作ったり
- PR のレビューコメントへの返信
- CI が落ちたときの原因調査＆自動修正

「この PR を見張っておいて」とお願いすれば、CI の結果やレビューコメントを受け取って、そのつど対応してくれます。しかも、イベントが来ると自動でセッションが起きてくれるので、**こちらが張り付いて待つ必要はありません**。ここ、地味にうれしいポイントです。

## はじめ方はかんたん

1. **環境を用意する**
   ブラウザで Claude Code のクラウド環境（`claude.ai/code` など）を開きます。対象のリポジトリやネットワークポリシー、環境変数、セットアップスクリプトを設定しておきましょう。

2. **セッションを始める**
   リポジトリを選んでセッションを立ち上げると、コンテナが起動してリポジトリが自動でクローンされます。ここまで待つだけ。

3. **やりたいことを伝える**
   「この関数のバグ直して」「テスト足しといて」みたいに、ふつうの言葉でお願いすればOK。エージェントがコードを読んで、直して、必要ならテストも走らせてくれます。

4. **コミット & プッシュ**
   できあがったら、コミットしてブランチへプッシュ。くり返しになりますが、**プッシュしないと成果は残らない**ので、ここだけはお忘れなく。

## セットアップスクリプトで最初から快適に

プロジェクトによっては、テストやリンターを動かすのに依存関係のインストールが必要ですよね。そんなときは **SessionStart フック**やセットアップスクリプトの出番。セッションが始まったタイミングで自動で環境を整えてくれるので、Web セッションでもローカルと同じように `npm test` や lint がすんなり動く状態を作れます。最初に少し仕込んでおくと、あとがぐっとラクになります。

## ちょっとした注意点

- **ディスクは固定枠**: 書き込めるディスクはセッションごとの固定枠です。`No space left on device` が出ても慌てずに。いらないビルド成果物やキャッシュを消せば、その分すぐに書けるようになります。
- **成果は必ずプッシュ**: 何度も言ってすみません。でも本当に大事なので！ 残したい変更はコミット & プッシュを忘れずに。
- **ブラウザは最初から入ってます**: Chromium がプリインストール済みで、Playwright も設定済み。`playwright install` を実行する必要はありません。

## おわりに

Cloud Code のいいところは、なんといっても**「環境に縛られず、どこからでも AI にサッと開発を頼める」**こと。使い捨てのきれいなコンテナ、GitHub との仲のよさ、開始時の自動セットアップ——このあたりがそろっているおかげで、スマホからの指示や PR の自動対応みたいに、これまで手間だった作業がずいぶんラクになります。

まずは小さなタスクからで大丈夫。気軽にブラウザから Claude Code に話しかけてみてください。きっと「あ、これ便利かも」と思えるはずです 🙂
